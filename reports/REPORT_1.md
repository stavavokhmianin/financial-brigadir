## Бэклог этапа 2 (23–26 октября): импорт CSV, счета и обязательства, базовый баланс, риск

**A — backend/data**
- `POST /imports/csv`: шаблон CSV, предпросмотр, сопоставление колонок, ошибки по строкам,
  fingerprint и `Idempotency-Key`, лимит размера, экранирование формул.
- Подтверждение и отмена inferred-обязательств (`POST /obligations` с `confirm`).
- `POST /forecasts`: сборка `ForecastInputSnapshot` из реестра, запись `ForecastRun`.

**C — forecasting/QA**
- `forecast_core`: уровень 0 (календарь) + уровень 1 (медиана трат по дням недели без
  переводов, возвратов и обязательств). Дневной `B_t`, нарушение резерва `B_t < R_t`, дата риска.
- Эталоны 12.4 на профилях генератора: ожидаемый минимум, дата разрыва, влияние покупки на 12 000 ₽.
- Baseline A/B из `docs/experiment-plan.md` на `hidden_future`.

**B — client/product**
- Экраны: прогноз по дням (p10/p50/p90), календарь (11.2), ручное добавление счёта и
  обязательства, загрузка CSV с предпросмотром.
- Состояние «данные устарели» и честные диапазоны вместо одного числа.

## Как команда работает дальше

- Код идёт в `step4ik` (или в `feat/*` → PR → `step4ik`). На каждый push CI прогоняет ruff,
  mypy, pytest на SQLite и PostgreSQL, `tsc`, тесты и web-сборку клиента, compose со smoke-тестом.
- Новый эндпоинт: код → `export_openapi.py` → `openapi.yaml` в том же коммите. Клиент получает
  типы автоматически при `npm install`.
- После каждой задачи — отчёт `reports/REPORT_<этап>.<задача>.md` в `master`.
