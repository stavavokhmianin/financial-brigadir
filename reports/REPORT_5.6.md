# REPORT 5.6 — Нативный Android и проверка скорости API

Дата: 21.10.2026. Код: [`dbaa53c`](https://github.com/stavavokhmianin/financial-brigadir/commit/dbaa53c), `step4ik`.

## Проверка API на стенде

Добавлен `scripts/benchmark_api.py`: создаёт отдельный демо-профиль, импортирует
10 000 синтетических операций, измеряет API прогноза/сценария после импорта и
удаляет только собственный профиль. В логах и результате нет токена.

Источник результатов: `docs/backtest/api-latency-stage5.json` в кодовой ветке.
Windows, Python 3.12.14, по три последовательных запроса на локальный API:

| Операция | Максимальная задержка | Ориентир ТЗ |
|---|---:|---:|
| Прогноз демо | 0,0503 с | до 2 с (§26.1) |
| Прогноз после импорта 10 000 строк | 0,1793 с | до 3 с (§13.4) |
| Сценарий после импорта | 0,4853 с | до 3 с (§13.4) |

Импорт не включается во время расчёта. Это локальный latency smoke, не нагрузочный
тест и не измерение p95. Все пороги пройдены; Ruff, format и mypy нового скрипта чистые.

## Нативная сборка

В [запуске Android](https://github.com/stavavokhmianin/financial-brigadir/actions/runs/39584818112)
собран standalone APK, 39 838 027 байт, ARM64 + x86_64. Контрольная сумма APK:

`5b3ca43fee8b471e3b12867a6e5d1f1c4f0508ca34dfd038c810348d9d36dc6b`

Артефакт скачан и проверен по digest GitHub; обе архитектуры подтверждены внутри APK.
Первый E2E не дошёл до приложения: при установке системного образа закончился диск runner.
Сборка и эмулятор разделены на отдельные jobs. Для повторного E2E можно безопасно
переиспользовать APK по run id: workflow сверяет дерево исходников клиента и отказывает
при несовпадении (тестовый flow исключён из сравнения).

Подготовлена прокрутка стартового экрана в Maestro для небольших дисплеев.
Повторный прогон на свежем runner запущен; окончательный результат будет добавлен
после завершения. Наличие APK не подменяет проверку UI и физического устройства.
