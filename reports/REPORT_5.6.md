## Проверка API на стенде

Добавлен `scripts/benchmark_api.py`: создаёт отдельный демо-профиль, импортирует
10 000 синтетических операций, измеряет API прогноза/сценария после импорта и
удаляет только собственный профиль. В логах и результате нет токена.

Источник результатов: `docs/backtest/api-latency-stage5.json` в кодовой ветке.
Windows, Python 3.12.14, по три последовательных запроса на локальный API:

| Операция | Максимальная задержка | Ориентир ТЗ |
|---|---:|---:|
| Прогноз демо | 0,0503 с | до 2 с (§26.1) |
| Прогноз после импорта 10 000 строк | 0,1793 с | до 3 с (§13.4) |
| Сценарий после импорта | 0,4853 с | до 3 с (§13.4) |

Импорт не включается во время расчёта. Это локальный latency smoke, не нагрузочный
тест и не измерение p95. Все пороги пройдены; Ruff, format и mypy нового скрипта чистые.

## Проверка установленного приложения

В [прогоне 39588580787](https://github.com/stavavokhmianin/financial-brigadir/actions/runs/39588580787)
APK установлен и запущен на Android 34. Пройдены демо, сценарная покупка с высоким
риском, переключение Free и Plus. Банковская проверка остановилась на поиске текста
результата; этот прогон не считается полным E2E. Три скриншота подтверждают пройденные шаги.

Для диагностики добавлен `scripts/android_e2e.py`: при падении сохраняет скриншот,
UI XML, AndroidRuntime log и лог API; Maestro сохраняет JUnit и debug-файлы.
Регулярное выражение банковского сообщения учитывает переносы строк.

При повторных холодных стартах Google APIs образа зафиксированы системные ANR
Android System UI/Pixel Launcher/system, перекрывшие приложение. В workflow
выделено место для userdata и уменьшено разрешение экрана. Регулярный CI переведён
на более лёгкий Android 11 AOSP (API 30), Google-сервисы приложению не нужны.
Известные диалоги System UI/Pixel Launcher могут ожидаться только на старте;
падение самого приложения по-прежнему делает проверку красной.
