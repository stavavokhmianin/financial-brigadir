## Сервер и решения

VPS: Ubuntu 24.04, 1 vCPU, 1 ГБ памяти, панель хостинга ISPmanager. Из этого вытекают решения:

| Ограничение | Решение |
|---|---|
| 1 ГБ памяти, ~270 МБ свободно | Без Docker: нативный API под systemd (~85 МБ) и SQLite. Web собирается на машине разработчика |
| Порт 80 занят nginx панели | Caddy только на 443. Сертификат Let's Encrypt подтверждается через TLS-ALPN, панель не трогаем |
| Нет домена | `5-35-98-96.sslip.io` — DNS-имя, указывающее на IP. Сертификат выдан на него |
| Пароль сервера в чате | Отдельный ключ `brigadir_deploy`. Пароль не использовался, владельцу рекомендовано сменить |

## Что сделано

- **`infra/stand/deploy.sh`.** Выкатка текущего коммита одной командой:
  - сборка web под адрес стенда;
  - код из `git`;
  - загрузка релиза на сервер;
  - запуск настройки сервера;
  - проверка снаружи по HTTPS.
- **`infra/stand/remote-setup.sh`.** Идемпотентная установка:
  - пакеты и отдельный пользователь `brigadir`;
  - venv, релизы с переключением ссылки `current` (хранятся три последних);
  - web без простоя;
  - сервисы и проверка здоровья API.
- **`brigadir-api.service`:**
  - API слушает только localhost, реальный IP клиента приходит от Caddy;
  - миграции применяются при старте;
  - песочница systemd: писать можно только в данные стенда;
  - `MemoryMax=350M`.
- **Caddy:** HTTPS (TLS 1.3), HSTS, CSP, `X-Frame-Options`, сжатие, долгий кэш для хэшированных
  файлов сборки.
- **`brigadir-maintenance.timer`.** Раз в 6 часов:
  - удаление заброшенных демо-профилей старше 7 дней — новая команда `app.cli retention`, с тестом;
  - онлайн-бэкап SQLite, хранятся 7 последних.
- **Workflow «Stand APK».** ARM64-APK с адресом стенда: устанавливаешь и пользуешься, адрес
  вводить не нужно. Перед публикацией артефакта проверяет, что стенд жив.
- **Аудит npm.** После мержа CI нашёл новую high-находку `decode-uri-component`
  (GHSA-qr28-fpjm-wq7f). Исправление есть только в ESM-версии 0.5.1, а `query-string` в
  expo-router подключает пакет через `require()`: override сломал бы навигацию. Находка принята
  в allowlist с обоснованием (DoS только на устройстве пользователя), снятая `braces` убрана.
- **Документация.** `docs/stand.md`: устройство, выкатка, логи, восстановление из бэкапа, переход
  в режим пилота. Ссылки на стенд — в README и в сценарии демо.

## Проверки на живом стенде

- **Сертификат:** Let's Encrypt (YE2), TLS 1.3, до 27.01.2027, продлевается автоматически.
- **Сквозной сценарий демо 16.4** через API стенда (`demo_walkthrough.py --api https://…`): все
  числа совпали с эталоном, включая учебный банк и подавление повторного предупреждения.
- **Обход всех экранов в браузере** против стенда (`qa_screens.py`): 4 профиля × 9 экранов без
  ошибок.
- **Сервер:**
  - API и Caddy активны, API занимает 85 МБ, свободно 409 МБ;
  - порт 8010 снаружи недоступен, открыт только 443;
  - таймер обслуживания отработал успешно, первый бэкап создан.
- **CI на `master` (`0e89eee`):** зелёные CI, Android APK + E2E на эмуляторе, демо-видео и обход
  экранов, Stand APK (стенд проверен из GitHub Actions перед публикацией артефакта).

## Что остаётся

- **Сменить пароль сервера** (`passwd`): он был в чате.
- **Режим пилота.** Чтобы пустить на стенд реальные данные, нужны условия из `docs/pilot.md`
  (шифрование диска, 152-ФЗ). Режим включается одной строкой `APP_MODE=pilot`.
- **Выкатка из CI** возможна: нужен приватный ключ в секретах репозитория, их добавляет
  владелец. Пока выкатка — `infra/stand/deploy.sh` с машины разработчика.
