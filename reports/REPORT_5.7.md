## Исправлено

1. **Синхронизация с учебным банком блокировала весь сервер.** Обработчики `sync` и
   `revoke` были `async` и при этом работали с синхронной БД прямо в event loop. Пока шла
   загрузка ~500 операций, остальные запросы ждали, даже `/health`.
   - Теперь обработчики синхронные и выполняются в пуле потоков.
   - Чтение коннектора идёт в event loop через `anyio.from_thread`. Так настоящий банковский
     адаптер с сетевыми запросами тоже не будет блокировать сервер.
2. **Устаревшее имя модуля.** `planned.py` (заглушки 501 «будет на следующем этапе»)
   переименован в `bank_mock.py` для роутера и схем. Удалён неиспользуемый ответ
   `501 not_implemented`. OpenAPI не изменился: контрактный тест пройден.
3. **Android E2E** запускался на любой push в API и пакеты: это 20–30 минут эмулятора из
   лимита Actions приватного репозитория.
   - Теперь на push он запускается только при изменении клиента или самой проверки.
   - Изменения API покрывает основной CI. Полный прогон доступен вручную (`workflow_dispatch`).
4. **Тексты клиента.** Новые подписи дашборда и симулятора вынесены в `ru.ts`, как во всём
   клиенте. Строка «Расчётный лимит покупки при выбранном риске» читалась странно на
   дашборде, где риск никто не выбирает. Теперь это «По расчёту резерв сохранится при
   покупке … до N ₽»: это по-прежнему не гарантия.

## Замечания без изменений

- **Выход отзывает все сессии профиля, а не только текущую.** Для демо-профиля с одной
  сессией это то же самое.
- **Ограничение частоты запросов** считается на процесс и по IP. За общим прокси все клиенты
  делят один лимит. Это уже указано как условие пилота (общий limiter).
- **Блокировка строки пользователя** при каждом прогнозе сериализует расчёты одного
  пользователя (до ~0,5 с). Это допустимо, но для пилота её можно ослабить.
- **Экраны «Учебный банк», «Приватность» и «Free и Plus»** держат тексты прямо в компонентах.
  Перенос в `ru.ts` стоит сделать вместе с остальной полировкой интерфейса.
