# REPORT 6.1 — Качественная шкала риска

- **Этап:** 6 (30 ноября – 8 декабря 2026, спринт 3)
- **Роль по 16.1:** B + C
- **Коммит:** [`0212c7a`](https://github.com/stavavokhmianin/financial-brigadir/commit/0212c7a) в `step4ik`

Решение команды: риск показываем шкалой «низкий / средний / высокий», проценты не показываем.

## Что сделано

- **Шкала из трёх ступеней** на дашборде, в прогнозе и в симуляторе. Активная ступень залита
  цветом уровня. Под шкалой подпись словами о сценариях, без чисел:
  - «Резерв сохраняется даже в плохом сценарии»;
  - «Ниже резерва — только в плохом сценарии»;
  - «Ниже резерва уже в базовом сценарии».
- **В симуляторе виден сдвиг:** прежняя ступень отмечена пунктиром и словом «было», рядом
  «Риск вырос / снизился / не изменился». В таблице «Что изменится» строка «Риск» тоже
  показывает ступени. Так шаг 3 демо 16.4 выполняется без процентов.
- **Доступность:** у шкалы есть озвучиваемая подпись, например «Уровень риска: Средний →
  Высокий». Контраст проверен в светлой и тёмной теме.
- **ADR-0006.** Ступени совпадают с порогами `risk_level` в API, для `mc-0.1` и
  `baseline-0.1`. Проценты появятся только после калибровки на реальной истории.
- **Вероятности в API остаются** для бэктеста и банковской интеграции. Новый клиентский
  тест падает, если экран начнёт читать `gap_probability` или `risk_probability`.
- **Сценарий демо** (`docs/demo-script.md`):
  - шаг 3 идёт через шкалу «Средний → Высокий»;
  - шаг 5 показывает предупреждение с подавлением повтора и учебный банк, которые
    появились на этапах 4–5.
