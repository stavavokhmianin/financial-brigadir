- `openapi.yaml` экспортируется из FastAPI скриптом `services/api/scripts/export_openapi.py`.
  Тест `test_openapi_contract.py` проверяет:
  - файл совпадает с кодом;

  - все поля `*_minor` — целые.
- Клиент генерирует из файла TypeScript-типы (`openapi-typescript`, задача 1.5).

### Реализовано

| Метод | Что делает |
|-------|------------|
| `GET /health`, `GET /health/ready` | liveness и readiness с проверкой БД |
| `GET /demo/profiles` | профили для экрана запуска, у `family` стоит `mvp=false` |
| `POST /demo/sessions` | изолированный профиль из seed (FR-01): пользователь, источник, счета, операции, обязательства, доходы, токен |
| `GET /accounts` | счета, `liquid_balance_minor` через `forecast_core` (без лимитов, депозитов и блокировок), метка качества данных |
| `POST /accounts` | ручной счёт и остаток (FR-03); у кредитки обязателен лимит, кредитка и вклад по умолчанию не ликвидны |
| `GET /transactions` | фильтры (счёт, даты, тип, статус) и курсорная пагинация |
| `GET /obligations` | обязательства и календарь платежей в окне дат; 31-е число → последний день месяца |
| `POST /obligations` | ручное обязательство, статус `confirmed` |
| `PATCH /notification-settings` | режим, тихие часы (только парой), лимит некритичных сообщений 0–14 |

### Зафиксированы, отвечают `501` с указанием этапа

`POST /imports/csv` (multipart + `Idempotency-Key`), `POST /forecasts`, `GET /forecasts/{id}`,
`POST /scenarios`, `GET /alerts`, `POST /connectors/bank-mock/sync`. Схемы ответов уже
описаны: `ForecastOut` с `data_as_of`, `quality.coverage`, `quality.confidence`
(`illustrative`/`calibrated`), `model_version`, `risk_drivers` и точками p10/p50/p90 — ровно
то, что требует 22.3.

### Инфраструктура API

- Авторизация: `Bearer`, токен 32 байта, в БД только SHA-256, TTL 24 ч. `user_id` берётся
  из токена. Чужой объект → `404`.
- Единый формат ошибок `{"error": {"code", "message", "details"}}`.
- `SyntheticDataAdapter` загружает только `known` из генератора: скрытое будущее в БД не попадает.
- Запись операций идемпотентна по `(account, source, external_id)`, возвраты связываются с
  покупками. Повторная выгрузка из профиля `two_banks` при создании сессии отбрасывается как
  дубли — это видно в `summary.duplicates_skipped`.
- Контракт `BankConnector` (22.4): `ConsentToken`, `SourceAccount`, `SourcePage`, `SourceBalance`.
- Метка качества (13.2): охват, `data_as_of`, длина истории, устаревание (> 3 дней),
  предупреждения на русском (один банк, короткая история, кредитный лимит).
- `forecast_core.calendar.occurrences` — уровень 0 «достоверный календарь» из 23.1.
- Smoke-тест `scripts/smoke.py` идёт по демо-сценарию: readiness → профили → сессия →
  остаток 55 000 ₽ → календарь. В compose и CI он запускается автоматически.

## Тесты

- `test_api.py` — 36 тестов:
  - демо-сессия и одинаковые числа при одинаковом seed;
