# Пилотный и on-prem-контур

Раздел 16.2 (спринт 3: режим пилота, on-prem-профиль), разделы 18 и 25 ТЗ.
Файлы лежат в `infra/pilot/`. Проверяются CI-задачей `pilot-smoke` на каждый push.

## Чем пилот отличается от демо

| | Демо (`infra/compose.yaml`) | Пилот (`infra/pilot/compose.yaml`) |
|---|---|---|
| Вход | демо-профиль из seed | персональный код участника + принятие условий |
| Данные | синтетика | вносит участник: счета, обязательства, CSV |
| `/demo/*`, учебный банк | есть | 404 `not_available` |
| Swagger UI | `/api/v1/docs` | выключен (грузит скрипты с CDN) |
| Снаружи доступно | API :8000 | только TLS-прокси :8443 |
| Выход API в интернет | есть | нет: сеть `backend` с `internal: true` |
| Секреты | переменные окружения | файлы docker secrets |
| Лимит запросов | на процесс API | общий в nginx + на процесс API |
| Удаление после бэкапа | — | журнал удалений на отдельном томе |

Режим задаётся одной переменной `APP_MODE=pilot`. Клиент узнаёт режим из `GET /api/v1/meta`
и показывает либо выбор демо-профиля, либо вход участника.

## Запуск

```bash
cd infra/pilot
./init-secrets.sh                  # db_password, database_url, backup_key в secrets/
./make-dev-cert.sh                 # только для проверки; в банке — сертификат его УЦ
PUBLIC_ORIGIN=https://localhost:8443 docker compose up -d --build --wait
```

`PUBLIC_ORIGIN` — адрес, по которому участники открывают сервис. Он встраивается в web-сборку
и задаёт CORS. Для мобильного клиента тот же адрес передаётся в `EXPO_PUBLIC_API_URL`.

## Участники

```bash
docker compose exec api python -m app.cli invite --count 10 --days 30   # выдать коды
docker compose exec api python -m app.cli list-codes                    # без секретов
docker compose exec api python -m app.cli revoke-code pac_…             # отозвать
```

- **Код** — 16 символов без похожих букв и цифр (80 бит). В БД хранится только SHA-256,
  выводится один раз в терминал оператора. Передавайте коды по защищённому каналу.
- **Первый вход** создаёт пустой профиль (тариф Plus, без оплаты) и фиксирует версию условий
  `PILOT_TERMS_VERSION`. Повторный вход по тому же коду открывает тот же профиль.
- **Срок сессии** не дольше срока кода. Отзыв кода закрывает новые входы. Удаление профиля
  делает код недействительным.
- **Подбор кода** ограничивает nginx: не больше 6 попыток в минуту с адреса.

## Бэкап и восстановление

```bash
./backup.sh                         # backups/brigadir-<время>.sql.gz.enc, AES-256 + PBKDF2
./restore.sh backups/<файл>         # загрузка дампа и повтор удалений
```

Восстановление старого бэкапа вернуло бы профили, удалённые после него. Раздел 25 требует, чтобы
удаление охватывало и резервные копии, поэтому:

1. При удалении id профиля пишется в таблицу `erasure_log` и в файл на томе `erasures`.
   Пишется только случайный id, без данных профиля. Файл в бэкап БД не входит.
2. `restore.sh` после загрузки дампа вызывает `python -m app.cli reapply-erasures`. Команда
   удаляет все профили из журнала, которые снова появились в БД.
3. CI проверяет полный цикл: профиль → бэкап → удаление → восстановление → «повторно
   удалено профилей: 1» → вход по старому коду отклонён.

`secrets/backup_key` храните отдельно от бэкапов. Без ключа бэкап не прочитать, и восстановить
его тоже нельзя.

## Что обеспечивает оператор контура

Эти пункты не закрываются кодом, их нужно подтвердить на конкретной площадке:

- шифрование диска с томами `pgdata` и `erasures` (LUKS или средства хостинга/банка);
- сертификат от УЦ площадки вместо самоподписанного, автоматическое обновление;
- срок хранения бэкапов (предложение: 30 дней) и их удаление по сроку;
- мониторинг доступности и журналов без финансовых данных (API их не пишет);
- обновление образов `postgres`, `nginx`, `python`, `node` в поддерживаемых версиях;
- юридическая часть: 152-ФЗ, текст условий пилота, контакт для обращений участников.

## Ограничения

- Один экземпляр API. Для нескольких реплик достаточно общего limiter в nginx: состояние
  сессий и данных уже в PostgreSQL.
- Токен в клиенте живёт только в памяти. После перезапуска приложения участник снова вводит
  код. Это осознанный выбор вместо хранения токена на устройстве.
- Push-уведомлений нет. Предупреждения видны в приложении (раздел 16.2: push не блокирует релиз).
