# Учебный банковский адаптер (ТЗ 22.4)

`BankMockConnector` реализует `BankConnector` и читает синтетический профиль
`young_specialist`, seed 901. Ни одного запроса к банковской сети нет.

1. В клиенте открыть «Учебный банк» и явно разрешить чтение счетов, остатков и операций.
2. Согласие действует максимум 24 часа; разрешения проверяются на каждом методе адаптера.
3. Выбрать сценарий и синхронизировать. Добавится отдельный синтетический счёт;
   данные существующего демо-профиля не заменяются. Для эталонного демо 16.4
   используйте новый профиль без добавленного учебного счёта.
4. Отозвать доступ: последующие синхронизации получают 403. История остаётся до
   удаления профиля; повторное разрешение не создаёт вторую копию счёта.

API: `GET/POST/DELETE /api/v1/connectors/bank-mock/consent`,
`POST /api/v1/connectors/bank-mock/sync`. Для POST согласия нужны `accepted: true`,
`scopes: ["accounts", "balances", "transactions"]`, опционально `ttl_hours` (1–24).

| scenario | Поведение |
|---|---|
| ok | Все страницы по 50 операций, полный остаток |
| duplicates | Повтор 20 записей; уникальные операции и баланс не удваиваются |
| partial | Половина истории, флаг неполноты в источнике/качестве прогноза |
| network_error | Сбой на второй странице, 503 + Retry-After, никаких частичных записей |
| consent_expired | Имитация истечения согласия, 403 без записи |
| delayed | Снимок двухдневной давности; затем ok догружает историю и обновляет баланс |

После 503 пользователь повторяет запрос с `ok`: сервер не запускает бесконечные повторы.
При `delayed` после уже свежего снимка возвращается 409. Идемпотентность обеспечивается
стабильным источником/счётом и идентификаторами транзакций. PostgreSQL блокирует строку
согласия при sync/revoke/renew, поэтому отзыв не обгоняется новой синхронизацией.
SQLite — для однопроцессного локального демо, не для конкурентного пилота.

Согласия экспортируются и удаляются вместе с профилем. Миграция `0006` обязательна.
Живой адаптер потребует отдельной проверки ответов банка, протокола авторизации,
таймаутов, ретраев и хранения секретов; этот мок не доказывает готовность интеграции ВТБ.
