# Модель угроз (черновик этапа 1)

Основание: разделы 13.1 и 25 ТЗ. Документ обновляется при появлении импорта CSV
(этап 2) и банковского мок-адаптера.

| Угроза | Где возникает | Мера в MVP | Статус |
|--------|---------------|------------|--------|
| Доступ к объекту по чужому идентификатору (IDOR) | все `GET/POST /api/v1/*` с id | `user_id` берётся из токена сессии; объекты ищутся по паре `(id, user_id)`, чужой id → 404 | этап 1: accounts, transactions, obligations + тесты |
| Утечка токена сессии | клиент, логи | токен — 32 байта `secrets`, в БД хранится только SHA-256; TTL демо-сессии 24 ч; токен не логируется | этап 1 |
| SQL-инъекции | фильтры списков | только параметризованные запросы SQLAlchemy, сырой SQL запрещён | этап 1 |
| Финансовые данные в логах | API, воркер | в логах нет сумм, назначений платежей и токенов; логируются id и коды | этап 1 (правило), проверка — этап 2 |
| CSV-формулы и большие файлы | импорт CSV | лимит размера, экранирование `=+-@`, без доступа к файловой системе | этап 2 |
| Повторная доставка/импорт | импорт, мок банка | уникальность `(account_id, source, external_id)`, fingerprint импорта, `Idempotency-Key` | схема — этап 1, API — этап 2 |
| Подмена ответа банка | `BankConnector` | живого коннектора нет; мок читает синтетику | этап 2+ |
| Prompt injection в назначении платежа | LLM (после MVP) | LLM выключена, в P0/P1 тексты собираются из шаблонов | вне MVP |
| Раскрытие семейных трат | Family (P2) | нет в MVP | вне MVP |

Запрещено по архитектуре: запрашивать логины и пароли интернет-банка, копировать SMS-коды,
инициировать платежи.
