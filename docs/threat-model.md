# Модель угроз MVP (обновление этапа 6: пилотный контур)

Основание: разделы 13.1 и 25 ТЗ. Проверки и ограничения приведены для демонстрационного
MVP; подтверждения промышленного контура здесь нет. Политика данных: `privacy.md`.

| Угроза | Где возникает | Мера в MVP | Статус |
|--------|---------------|------------|--------|
| Доступ к объекту по чужому идентификатору (IDOR) | все `GET/POST /api/v1/*` с id | `user_id` берётся из токена сессии; объекты ищутся по паре `(id, user_id)`, чужой id → 404 | этап 6: `test_security_idor.py` обходит все пути OpenAPI с id; новый путь без проверки роняет тест |
| Утечка токена сессии | клиент, логи | 32 байта энтропии, в БД только SHA-256, TTL 24 ч, серверный отзыв всех сессий, no-store | реализовано; `test_privacy.py` |
| SQL-инъекции | фильтры списков | только параметризованные запросы SQLAlchemy, сырой SQL запрещён; Ruff S608 | `test_quality_review.py` (`' OR 1=1 --` в пути и фильтре) |
| Финансовые данные в логах/ошибках | API, воркер | ошибки валидации не отражают входы; параметры SQL скрыты; воркер пишет тип ошибки | реализовано; `test_privacy.py` |
| CSV-формулы и большие файлы | импорт CSV | лимит 2 МБ и 20 000 строк, экранирование `=+-@`, файл не сохраняется на диск | этап 2: реализовано и покрыто тестами |
| Повторная доставка/импорт | импорт, мок банка | уникальность `(account_id, source, external_id)`, fingerprint импорта, `Idempotency-Key` (409 при другом файле) | этап 2: реализовано |
| Подмена/устаревание ответа банка | `BankConnector` | только синтетика; старый снимок не заменяет свежий; ошибка страницы не оставляет частичный импорт | реализовано для мока; живой адаптер требует отдельной проверки |
| Prompt injection в назначении платежа | LLM (после MVP) | LLM выключена, в P0/P1 тексты собираются из шаблонов | вне MVP |
| Раскрытие семейных трат | Family (P2) | нет в MVP | вне MVP |
| Обход ограничений Free/Plus | счёт, прогноз, сценарий, банковский мок | серверная политика, блокировка профиля при создании счёта/смене режима, запрет самоповышения вне демо | `test_plans.py`; `plans.md` |
| Бессрочное хранение недоступного демо | БД, расчёты, аудит | экспорт/удаление всех связанных данных; worker retention 7 дней для недоступных демо | `test_privacy.py`; для автоочистки требуется работающий воркер |
| Синхронизация после отзыва | согласия банковского мока | срок/scopes проверяются на каждом чтении; отзыв и sync сериализуются на строке согласия в PostgreSQL | `test_bank_mock.py`; реального доступа нет |
| Перегрузка запросами/большим multipart | вход API | лимит тела до парсинга и rate limit на процесс; в пилоте — общий limiter nginx и `client_max_body_size` | `test_privacy.py`; CI `pilot-smoke` получает 429 |
| Подбор кода участника пилота | `POST /pilot/sessions` | 80 бит энтропии, в БД только SHA-256, 6 попыток/мин с адреса в nginx, единый ответ без причины отказа | `test_pilot.py`; CI `pilot-smoke` |
| Перехват трафика | клиент ↔ сервер | в пилоте только TLS 1.2/1.3, HSTS; API и БД не опубликованы наружу | CI `pilot-smoke` |
| Утечка данных наружу из контура (раздел 18) | API, воркер | сеть `backend` с `internal: true`, LLM и внешних вызовов нет, Swagger UI выключен | CI: `egress_check.py` из контейнера API |
| XSS/кликджекинг в web-клиенте | браузер | CSP `script-src 'self'`, `frame-ancestors 'none'`, `nosniff` | CI `pilot-smoke` проверяет заголовки |
| Восстановленный бэкап возвращает удалённый профиль | бэкапы | журнал удалений вне БД, `restore.sh` → `reapply-erasures` | `test_pilot.py`; CI: бэкап → удаление → восстановление |
| Кража бэкапа | хранилище бэкапов | AES-256 + PBKDF2, ключ отдельно от бэкапов | CI проверяет, что файл не читается как gzip |
| Секреты в переменных окружения/логах | контейнеры | docker secrets файлами, `.dockerignore`, в git не попадают | `infra/pilot/init-secrets.sh` |
| Уязвимые зависимости | Python, npm | `pip-audit`; шлюз `npm audit` с allowlist и сроком пересмотра | CI; `apps/client/audit-allowlist.json` |

Пилотный контур описан в `pilot.md`. На площадке остаётся подтвердить шифрование дисков,
сертификат УЦ, срок хранения бэкапов, мониторинг и юридическую часть (152-ФЗ, условия).
`users.is_demo` позволяет переключать демонстрационный тариф; этот флаг задаёт сервер,
публичного способа изменить его у клиента нет. В демо не следует загружать реальные выписки.

Запрещено по архитектуре: запрашивать логины и пароли интернет-банка, копировать SMS-коды,
инициировать платежи.
