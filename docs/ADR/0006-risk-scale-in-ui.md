# ADR-0006. Риск в интерфейсе — качественная шкала без процентов

- Статус: принято командой
- Дата: 2026-10-21
- Основание: разделы 9.3, 16.4 (шаг 3), ADR-0005

## Контекст

Шаг 3 демо 16.4 требует, чтобы после ввода покупки менялась «вероятность нарушения резерва».
По ADR-0005 проценты в интерфейсе скрыты. Бэктест на синтетике показал, что дневные
вероятности плохо откалиброваны (дневной skill −0,31, корзины смещены). Процент на экране выглядел бы
точнее, чем модель есть на самом деле.

## Решение

1. **Шкала из трёх ступеней.** Клиент показывает риск ступенями «Низкий / Средний / Высокий»
   на дашборде, в прогнозе и в симуляторе.
2. **Смысл ступеней.** Ступени — это те же пороги, что `risk_level` в API (ADR-0005, п. 2), и
   формулируются словами о сценариях, без чисел.

   | Ступень | API | Подпись | `mc-0.2` | `baseline-0.1` |
   |---|---|---|---|---|
   | Низкий | `low` | Резерв сохраняется даже в плохом сценарии | p < 0,1 | p10 выше резерва |
   | Средний | `medium` | Ниже резерва — только в плохом сценарии | 0,1 ≤ p < 0,5 | ниже только p10 |
   | Высокий | `high` | Ниже резерва уже в базовом сценарии | p ≥ 0,5 | медиана ниже резерва |

3. **В симуляторе виден сдвиг.** Прежняя ступень отмечается пунктиром и словом «было», под
   шкалой пишется «Риск вырос / снизился / не изменился». Так шаг 3 демо выполняется без
   процентов.
4. **В API вероятности остаются.** `gap_probability`, `risk_probability`, `delta_risk` нужны
   для бэктеста, будущей калибровки и банковского on-prem-интеграции. Клиентский тест
   `tests/risk-scale.test.ts` падает, если экран начнёт читать эти поля.

## Когда пересмотреть

Проценты можно показать только после калибровки на добровольной реальной истории (раздел 15).
Нужен положительный дневной skill по Brier score и корзины надёжности вдоль диагонали. До
этого `quality.confidence` остаётся `illustrative`.
