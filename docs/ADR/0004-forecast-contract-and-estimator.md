# ADR-0004. Контракт прогноза и выбор оценщика трат

- Статус: принято
- Дата: 2026-10-21
- Основание: разделы 9, 15.2, 22.3, 23.1 ТЗ

## Решения

1. **Контракт `ForecastOut`** сохраняет поля примера 22.3 (`forecast_id`, `data_as_of`,
   `quality.coverage`, `quality.confidence`, `baseline_risk`, `scenario_risk`, `risk_date`,
   `risk_drivers`, `model_version`). К ним добавлены:
   - блок `risk`: уровень, дефицит, минимумы, объяснение, структурированные причины;
   - `start_balance_minor`, `reserve_minor`, `spending`, `scenario`;
   - потоки дня в `points`.
2. **Вероятности — `null`** до калибровки (раздел 9.3). Риск передаётся уровнем
   `low/medium/high` через сценарии p10/p50/p90, а не псевдопроцентом.
3. **Оценщик повседневных трат — среднее по дню недели без аномалий.** Медиана из ТЗ
   (baseline B) оставлена для сравнения. Выбор сделан по бэктесту на скрытом будущем
   генератора (`docs/backtest/baseline.md`) и будет пересмотрен на реальных данных.
4. **Сценарии**: `expense` и `income_shift` считаются прямо в `POST /forecasts`. С этапа 3
   `POST /scenarios` сравнивает «до/после» (до 10 событий сразу), а в каждом прогнозе есть
   `safe_to_spend` — диапазон суммы условно безопасной покупки (9.4).
5. **Хранение расчёта**: в `forecast_runs` пишутся компактный снимок без выписки, отпечаток
   полного снимка, версия модели, сценарий и итог (`result`), а в `forecast_points` —
   траектория. Миграция `0003`.
6. **Демо-время**: для демо-профиля расчёт идёт от даты выгрузки (19.10.2026), для реальных
   данных — от текущего момента. Данные старше 3 дней помечаются `stale_data`, уверенность
   становится `insufficient` (раздел 10.2: сначала обновить данные).
