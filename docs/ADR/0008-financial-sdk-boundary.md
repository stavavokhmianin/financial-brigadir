# ADR-0008: публичная граница Financial SDK

- Статус: принято
- Дата: 2026-11-01

## Контекст

Расчётное ядро уже было чистым Python-пакетом, но прикладной backend импортировал его
внутренние модули напрямую. Из-за этого не существовало одного стабильного контракта для
стороннего проекта, адаптеры банков жили в приложении, а транспортные детали смешивались
с выбором модели.

## Решение

Создать пакет `financial-sdk` как публичный слой над математическим `forecast-core`.

1. `FinancialData` является нейтральным входом, не ORM-моделью.
2. `FinancialEngine.forecast()` и `.simulate()` — основные use-case'ы.
3. Источники подключаются через синхронные или асинхронные адаптеры.
4. JSON-сериализация не зависит от FastAPI/Pydantic.
5. `forecast-core` сохраняет алгоритмы и версии `baseline-0.2`/`mc-0.3`, но является
   внутренней реализацией SDK.
6. Runtime-код «Финансового бригадира» импортирует только `financial_sdk`; это проверяет
   архитектурный тест.

## Последствия

- Одни и те же расчёты можно использовать из Python, worker, CLI или тонкого HTTP bridge.
- Банк, база данных и UI можно заменить без изменения моделей прогноза.
- Версия SDK и версии финансовых моделей меняются независимо.
- На первом этапе `financial_sdk` зависит от `forecast-core`; объединять пакеты физически
  не требуется, поскольку публичная граница уже отделена и проверяется тестами.
