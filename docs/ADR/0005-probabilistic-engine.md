# ADR-0005. Вероятностный движок и политика показа вероятностей

- Статус: принято
- Дата: 2026-10-21
- Основание: разделы 9.3, 9.4, 13.3, 15.2, 23.1 (уровень 2), FR-18

## Решения

1. **`mc-0.1` — модель по умолчанию** в `POST /forecasts` и `POST /scenarios`. На каждой из
   1000 траекторий разыгрываются:
   - бутстреп дневных трат того же дня недели;
   - разовые крупные покупки с исторической частотой;
   - поступление дохода с его вероятностью, в первый день окна с долей 0,6 или позже;
   - суммы неточных платежей из диапазона;
   - пропуск предполагаемых платежей с вероятностью 0,1.

   Параметры 0,6 и 0,9 — допущения, по бэктесту они не подбирались.
2. **Уровень риска** по вероятности нарушения резерва на горизонте: `high` ≥ 0,5,
   `medium` ≥ 0,1, иначе `low`. Дата риска — первый день, когда дневная вероятность
   достигает порога уровня.
3. **Безопасная сумма** считается строго по формуле 9.4: максимальная покупка, при которой
   доля траекторий с нарушением резерва остаётся ниже 0,5 («можно») или 0,1 («с запасом»).
   Граница точная, это проверяет тест «ровно на границе — не high, на копейку больше — high».
4. **Воспроизводимость (13.3)**: детерминированный ГСЧ, seed 0. База и сценарий считаются на
   одних и тех же случайных числах, поэтому их разница — эффект события, а не шум.
5. **Короткая история (< 28 дней)** — возврат к детерминированной `baseline-0.1` с флагом
   `simulation_skipped`. Бутстреп на паре недель создавал бы ложную точность.
6. **Политика показа (9.3).** API отдаёт `baseline_risk`, `scenario_risk`, `delta_risk` и
   дневные `risk_probability`, но `quality.confidence` остаётся `illustrative`. Бэктест на
   синтетике показал полезный, но неидеальный результат (`docs/backtest/baseline.md`):
   - по горизонту — Brier 0,087, skill +0,42;
   - по корзинам есть перекос: прогнозы 10–30 % на деле означают почти 0 %;
   - по дням skill только +0,04.

   Поэтому клиент **не показывает проценты**, только уровень риска, дату, причины и диапазоны.
   Числа появятся в интерфейсе после калибровки на реальных данных добровольцев
   (`confidence = calibrated`).
7. `baseline-0.1` остаётся в ядре: это fallback и эталон сравнения в бэктесте.
