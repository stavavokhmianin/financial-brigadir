# Free и Plus: политика возможностей (FR-28)

Сервер определяет возможности по `users.plan`; клиент не передаёт владельца или
доверенную версию тарифа в запросах на расчёт. Политика находится в `app/modules/plans.py`.

| Возможность | Free | Plus |
|---|---|---|
| Новые счета | до одного активного счёта | несколько |
| Базовый прогноз | до 30 дней | до 90 дней |
| Сценарная покупка | одна покупка | покупки и комбинации |
| Сдвиг дохода | нет | да |
| Ручные обязательства/доходы, уведомления | да | да |
| История, экспорт, удаление | да | да |

Ограничения проверяются на API создания счёта, синхронизации банковского мока,
`POST /forecasts` и `POST /scenarios`. Использование сохранённой 90-дневной базы после
понижения тарифа не позволяет обойти лимит сценария. Чтение сохранённых расчётов остаётся.
Создание счетов и смена режима используют одну блокировку строки пользователя в PostgreSQL.

При понижении до Free существующие счета, операции и прогнозы **не удаляются и не
скрываются**. Базовый расчёт продолжает учитывать все ранее добавленные счета:
выбрасывание части баланса создало бы ложную картину. API возвращает признак
`existing_accounts_over_limit`, интерфейс объясняет ограничение новых добавлений.
Банковский мок может обновлять существующий счёт после понижения, но не добавлять новый.

## Демо без оплаты

Новый демо-профиль начинает с Plus для полного показа возможностей. Экран «Free и Plus»
показывает активный режим и позволяет проверить оба через
`PATCH /api/v1/plans/demo-preview {"plan":"free"|"plus"}`. Проверки сервера
при этом настоящие, без обхода для демо. `GET /api/v1/plans` показывает каталог и состояние.

Эндпоинт переключения работает **только** для `is_demo=true`, не может повысить тариф
обычного пользователя и не принимает чужой user_id. Смена записывается в аудит.
Реальная оплата, активация подписки и Family не включены в MVP; `billing_enabled=false`.
Прежние демо-профили с Free сохраняют этот режим и могут переключиться явно.
