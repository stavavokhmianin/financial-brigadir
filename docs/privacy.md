# Приватность демонстрационного стенда

Версия: 21.10.2026. Реализует технические требования 13.1 и 25 ТЗ;
не является заключением о соответствии законодательству или банковским требованиям.

- В БД хранится только SHA-256 токена; выход отзывает все сессии профиля. Web-клиент сейчас
  сохраняет bearer-токен в `localStorage`, чтобы вход переживал закрытие вкладки. Это приемлемо
  только для синтетического демо: до работы с реальными выписками web-сессию нужно перенести
  в `HttpOnly; Secure; SameSite` cookie/BFF и добавить CSRF-защиту. Мобильный клиент должен
  хранить токен в системном Keychain/Keystore, а не в обычном AsyncStorage.
- `GET /api/v1/privacy/export` выгружает JSON: профиль, источники, счета, операции,
  обязательства, доходы, настройки, импорт, снимки и результаты расчётов, уведомления и аудит.
  Сессии и хэши токенов исключены. В web скачивается файл; на телефоне — системное меню
  передачи JSON-текста. Для больших выгрузок используйте web/API.
- `DELETE /api/v1/privacy/profile` с `{"confirmation":"DELETE"}` удаляет все перечисленные
  записи и сессии одной транзакцией. Другие профили не затрагиваются. HTTP-ответы — `no-store`;
  отдельного серверного кэша нет. Клиент закрывает профиль после успешного удаления.
- Исходный CSV приложение не сохраняет как артефакт. Multipart-парсер может использовать
  временный файл на время запроса; после завершения он закрывается. Общий входящий запрос
  ограничен 3 МиБ до парсера, собственно CSV — 2 МиБ.
- Недоступные демо-профили старше 7 суток удаляются до 100 за цикл. В Docker это делает
  worker, на публичном стенде — `brigadir-maintenance.timer` каждые 6 часов. Без одного из
  этих процессов автоматическая очистка не выполняется. Демо-сессия истекает через 24 часа,
  зарегистрированная — через 30 суток, пилотная — через 7 суток по умолчанию.
- Согласие не подставляется при создании демо. Банковский мок получает отдельное явное
  согласие на синтетические данные; настоящее банковское подключение отсутствует.
- Ошибки валидации не отражают значения входных полей. SQLAlchemy скрывает параметры
  ошибок; воркер пишет тип ошибки, без её текста. Логирование тела запроса запрещено.
- 120 изменяющих запросов в минуту на IP в одном процессе. За reverse proxy нужно явно
  настроить доверенные прокси, сетевые лимиты и общий rate limiter перед несколькими workers.
  Приложение само не доверяет заголовку `X-Forwarded-For`.

## Граница готовности

Локальный SQLite/HTTP предназначен для синтетики. Перед приёмом реальных выписок оператор
должен обеспечить HTTPS, шифрование дисков БД и резервных копий, ограничение доступа,
отдельный контур, добровольное согласие и опубликованный срок хранения. Приложение
не может подтвердить конфигурацию хостинга. Реальные данные в общий демо-стенд не загружать.

Для пилота установить максимальное хранение резервных копий 30 суток и проверить это
на инфраструктуре. После восстановления старой копии удалённые профили должны быть
повторно удалены **до** открытия доступа; журнал запросов на удаление хранить отдельно
от откатываемой БД. Сейчас такого производственного процесса нет — это блокер пилота,
а не реализованная гарантия. Локальный стенд резервных копий автоматически не создаёт.
