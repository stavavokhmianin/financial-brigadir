## Реализация

- Тёмная тема по умолчанию и согласованная светлая. Все пять заданных цветов присутствуют в системе. Семантические токены поверхностей, текста, границ, акцента, действий, графиков, наложений и теней; сохранены совместимые имена для существующих экранов.
- Типографическая шкала hero/display/title/heading/body/caption/eyebrow, локальные Geist Sans и Mono, табличные цифры. Кириллица, Ё/ё, рубль и цифры проверены в шести файлах шрифтов.
- `AppShell`: верхняя навигация на широком экране, нижние вкладки на мобильном, заголовки маршрутов, переключение темы, safe areas и корректировка iOS-клавиатуры. Тема сохраняется в браузере.
- `Surface`, `Card`, `Hero`, `Button`, `Field`, `Choice`, `Badge`, `Stat`, `LoadingState`, `ErrorState`, `EmptyState`, `SuccessState` оформлены как одна система. Старые имена компонентов и тестовые идентификаторы сохранены.
- Dashboard: отдельные роли баланса, доступной суммы, риска, прогноза, будущих платежей, счетов и истории. На мобильном краткая сводка риска и ближайшего платежа находится рядом с доступной суммой.
- Доступная сумма берётся из `safe_to_spend`, отображаются дата, основной и осторожный сценарии. Отсутствие данных не заменяется нулём. Семантика риска и пояснения сохранены.
- График: диапазон p10–p90, линия p50, резерв, сетка и подписи сумм, отметки критических точек. Касание выбирает дату; отдельные кнопки позволяют точно перейти между датами. Детализация показывает реальные p10/p50/p90 из ответа API. Сравнение исходного и изменённого сценария сохранено.
- Симулятор: исходный прогноз рядом с формой на desktop, график сравнения доступен сразу после расчёта, подробности остаются раскрываемыми.
- Календарь: будущие события вынесены вперёд, история отделена; даты, суммы, поступления и статусы имеют различимую иерархию.
- Онбординг: выразительная типографика, многослойная композиция из заданной палитры и объяснение трёх шагов. Сохранены учебный аккаунт, фиксированные профили и пилотный вход.
- Импорт: видимые этапы «Выписка → Проверка → Готово». Для добавления операций, уведомлений и дубликатов унифицированы состояния успеха и пустых списков.
- Тарифы сравниваются в двух колонках на desktop. Банковский сценарий и приватность используют общий каркас и новые элементы.
- Панели уведомлений и настроек учитывают safe areas; длинное содержимое уведомлений прокручивается. Зоны нажатия кнопок, выбора, навигации и действий учебного аккаунта увеличены до 44 pt и более.

## Движение и доступность

`MotionProvider` использует одну подписку на системный reduced motion. `Reveal` даёт короткие появления и последовательное раскрытие блоков. Кнопки используют spring scale, `Money` плавно обновляет числа. Для экранного диктора всегда доступно конечное реальное значение.

При reduced motion отключаются эти эффекты, а также анимация модальных панелей и нативной навигации. Бесконечных фоновых анимаций и новых анимационных зависимостей нет.

Поля имеют focus ring, ошибки объявляются через alert, сохранены accessibility labels и roles. Для web явно заданы ARIA-состояния радио, checkbox и раскрытия панелей; язык документа — русский. У кнопок выбора даты графика отдельные подписи, не совпадающие с управлением учебным временем.

## Воспроизведение

Используются существующие FastAPI и SQLite. Для локальной web-сборки:

```powershell
cd apps/client
$env:EXPO_PUBLIC_API_URL = 'http://127.0.0.1:8000'
npm run typecheck
npm test
npm run build:web -- --clear
npx expo export --platform android --platform ios --output-dir ../../artifacts/native-export
```

`--clear` полезен при смене адреса API: в этой среде Metro сначала использовал старое значение адреса из кеша.

После запуска локального API и web-сервера из корня проекта:

```powershell
.venv/Scripts/python.exe scripts/qa_screens.py --channel chromium --out artifacts/blue-final
.venv/Scripts/python.exe scripts/qa_design.py --channel chromium --out artifacts/blue-visual
```

`--channel` необязателен, если установлен стандартный Playwright headless shell. В этой среде использован полный Chromium. Новый `qa_design.py` выполняет проверку адаптивности, тем, графика и симулятора на реальном демо-API и сохраняет снимки.

Локально Node 22 установлен в `%LOCALAPPDATA%/financial-brigadir-tools/node-v22.23.4-win-x64`; перед CLI-командами его каталог нужно добавить в PATH текущего терминала. Python-зависимости находятся в `.venv`. Зависимости клиентского приложения не изменены.

## Границы проверки

Нативные бандлы успешно скомпилированы, но приложение не запускалось на физических Android/iOS-устройствах или iOS Simulator. Нативные жесты, экранные дикторы и производительность на среднем Android требуют отдельного device QA. На native выбор темы сохраняется в рамках текущего запуска.

Финансовое ядро, сервер, API-контракты, логика импорта и расчётов не изменены. В интерфейс не добавлены фиктивные финансовые данные или неработающие действия. Коммит, push и выкладка на публичный стенд не выполнялись.
