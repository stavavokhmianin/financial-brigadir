# Сценарий демо для ВТБ (3–4 минуты, раздел 16.4)

Цель — показать один понятный путь: **профиль → прогноз → покупка → изменение риска** и честно
обозначить ограничения. Все числа ниже воспроизводятся из seed 42 и проверяются автотестом
`services/api/tests/test_demo_16_4.py`.

## Перед показом (чек-лист)

- [ ] `docker compose up --build` — smoke-тест в логах зелёный (`ok …` в сервисе `smoke`).
- [ ] Клиент: `cd apps/client && npm install && npx expo start --web`; на телефонах — Expo Go,
      `EXPO_PUBLIC_API_URL` указывает на ноутбук.
- [ ] `python scripts/demo_walkthrough.py --api http://localhost:8000` — «Демо 16.4 прошло».
- [ ] Открыты вкладки: репозиторий (ветка `step4ik`), `docs/backtest/baseline.md`, презентация.
- [ ] Записано видео-страховка: полный проход по этому сценарию.

## План Б

1. **Нет интернета или Docker.** `python scripts/demo_walkthrough.py --offline` проходит те же
   шаги с API внутри процесса и печатает реплики и числа. Можно показывать прямо из терминала.
2. **Не работает клиент.** Показываем Swagger: `http://localhost:8000/api/v1/docs`,
   `POST /demo/sessions` → `POST /forecasts` → `POST /scenarios`.
3. **Ничего не работает.** Включаем видео-страховку. Видео — страховка, а не замена
   работающего продукта (16.4).

## Честные ответы на вероятные вопросы

- **«Данные настоящие?»** Нет, синтетика с 12 видами аномалий из ТЗ. Качество на реальных
  данных не доказано: это следующий шаг с добровольцами (раздел 15).
- **«Какая вероятность нехватки?»** В интерфейсе — ступень «низкий / средний / высокий»: без
  калибровки проценты были бы псевдоточными. В API вероятность есть для банковской интеграции
  и проверки модели (ADR-0006).
- **«Подключены к ВТБ?»** Нет. Есть контракт адаптера и работающий мок на синтетике. Живое подключение — только
  по официальному доступу, пароли банка никогда не вводятся.
- **«Чем лучше Дзен-мани и CoinKeeper?»** Мы не утверждаем, что лучше. Гипотеза — риск на
  конкретную дату, пересчёт до решения и редкие предупреждения. Её проверяют интервью и пилот.
