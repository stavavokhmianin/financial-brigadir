# План развития после финала

Основание: раздел 16.2 («После финала»), разделы 15, 17.4, 18, 26.3 ТЗ.
Принцип: каждое следующее вложение открывается только после проверки предыдущей гипотезы.
Эффект не заявляется без A/B-эксперимента.

## Где мы на 8 декабря

| Есть | Не доказано |
|---|---|
| Прогноз по дням, риск ниже резерва, сценарии «что если», предупреждения с подавлением повторов | Точность на реальном поведении людей: только синтетика |
| Пилотный/on-prem-контур: TLS, изоляция сети, зашифрованные бэкапы с повтором удалений | Калибровка вероятностей: дневной skill +0,04, проценты скрыты (ADR-0006) |
| Web, Android APK (эмуляторный E2E), видео демо в CI | Работа на физических устройствах, подписанный iOS |
| Финансовая модель с явными допущениями | Готовность платить, удержание, CAC: данных нет |

## Этапы

### 1. Добровольный пилот, 4–6 недель

Цель — первые реальные данные и честный ответ «полезен ли прогноз».

- 20–30 участников с регулярным доходом и обязательными платежами (раздел 2).
  Вход по коду, условия пилота, выписка CSV или ручной ввод.
- Еженедельно сравниваем прогноз с фактом по той же методике, что в бэктесте:
  MAE остатка, пойманные и пропущенные разрывы, ложные тревоги.
- Интервью до и после (гайд: `docs/research/interview-guide.md`).
- Пилот проходит в контуре `infra/pilot`. До старта площадка подтверждает шифрование
  дисков, сертификат и срок хранения бэкапов (`docs/pilot.md`).

**Критерий перехода:** модель P лучше календаря (A) по MAE и разрывам на реальной истории,
ложных тревог не больше одной в месяц на участника. Иначе — критерии остановки 15.4.

### 2. Калибровка и показ вероятностей

- Перекалибровать `mc-0.1` на данных пилота: доля дохода в срок, частота крупных трат.
- Показать проценты, только если дневной skill по Brier score положителен и корзины лежат
  у диагонали. Решение фиксируется новым ADR вместо ADR-0006.

### 3. Эксперимент с уведомлениями (раздел 15.3)

- Три группы: только календарь, событийные предупреждения, прогнозные предупреждения.
- Исходы: пропущенный обязательный платёж, отклик на подсказку, отключения, ложные тревоги.
- Push (Expo Notifications) включаем только для этого эксперимента. Режимы quiet/smart/active
  и лимит 2 в неделю уже есть.

### 4. Платёжный тест Free/Plus

- Серверная политика тарифов готова (FR-28). Нужна оплата (FR-29) и лендинг с ценой.
- Измеряем конверсию, удержание через 30/60 дней и CAC. Пересчитываем
  `scripts/business_model.py` на измеренных значениях, а не на допущениях.

### 5. Запрос интеграции с банком (раздел 18)

- Пакет для банка:
  - OpenAPI;
  - адаптер `BankConnector` с моком;
  - on-prem-профиль;
  - модель угроз;
  - результаты пилота с контрольной группой.
- Нужны: законный доступ к данным, управление согласиями, согласование контура, юридическая
  проработка 152-ФЗ и банковской тайны.
- Экономика для банка (раздел 17.4) считается только по экспериментальным данным пилота.

## Что не делаем, пока не подтверждены гипотезы

- **Семейный режим (Family).** Нужны отдельная модель доступа и согласий.
- **LLM-объяснения.** Тексты из шаблонов уже понятны; модель добавляет риск prompt injection.
- **Сложное ML вроде CatBoost.** Только если на реальных данных доказан выигрыш над простыми
  моделями (раздел 7.9).
