# synthetic_generator

Воспроизводимые синтетические профили для демо и эталонных тестов (раздел 12 ТЗ).

```bash
fb-synth --list
fb-synth young_specialist --seed 42 --out ys.json
```

```python
from synthetic_generator import generate

data = generate("two_banks", seed=42)  # dict, JSON-сериализуемый
```

## Профили

| id | Кто | Аномалии 12.3 |
|----|-----|---------------|
| `young_specialist` | зарплата двумя частями, аренда, потребкредит | задержка зарплаты, внеплановая медицинская трата |
| `credit_card` | траты по кредитке, рассрочка | покупка кредиткой + отдельное погашение, возврат и отмена, платёж 31-го в коротком месяце |
| `freelancer` | нерегулярные поступления, налог самозанятого, наличные | технический овердрафт, внеплановая трата, расхождение ручного и импортированного остатка |
| `two_banks` | зарплата в одном банке, траты в другом | переводы между своими счетами, частичный возврат, дубли с разной датой учёта, дыра в выписке, повторная загрузка |
| `family` (после MVP) | два участника | общая покупка с приватной частью, внутрисемейные переводы |

## Структура результата

- `known` — то, что известно на `as_of`: счета с остатками, операции (формат 8.2, деньги в
  `amount_minor`), ближайшие обязательства и ожидаемые доходы, `reupload` (повторная выгрузка),
  `manual_balances` (ручной ввод пользователя).
- `hidden_future` — что фактически произойдёт до `horizon_end`. Это эталон для бэктеста;
  в признаки модели не попадает.
- `anomalies` — какие аномалии внесены и в какие операции.
- `truth` — входящие остатки, id ложных дублей и операции, которых нет в выписке. Нужно для
  проверки инвариантов: `balance = opening + Σ(posted) − Σ(дубли) + Σ(потерянные)`.

Одинаковые `(profile, seed, as_of, months, horizon_days)` дают побайтно одинаковый JSON.
Генератор не использует алгоритм прогноза (раздел 23.1).
